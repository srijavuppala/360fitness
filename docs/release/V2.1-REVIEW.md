## Health-aware goals (Sakshi): feedback

**What's strong (keep it):**
- Health data lives outside `profile.answers`, with its own consent, its own optional backup collection and email-verified owner-only rules (`mobileHealthProfiles/{uid}`, revision + generation checks).
- The condition rules are a **reviewable table** with no medical numbers in code. A clinical advisor can review one file.
- Missing health data is `NOT_ASSESSED`, never "healthy". Clinician-provided values are shown as the clinician's, not the app's.
- Kidney: protein and carbs withheld, and the user can enter their nephrologist's protein number. This is the right pattern.
- Strong tests (health, privacy, nutrition goal, repository integration).

**Must fix (done in this PR):**
1. **Silent data loss** — fixed. If a saved health section failed validation, `parseSavedState` deleted it, and the next save of anything erased it for good. Now it is kept as `healthUnreadable` (the app still runs as "not assessed"), and "Remove my health information" clears both. Test added.

**Should change (next PR, owner: Sakshi):**
2. **Split "Diabetes (Type 1 / Type 2)"** into separate options. Type 1 and insulin-using type 2 need different handling. Our plan supports T2D/prediabetes self-management and must not hand a fitness-formula carb target to someone dosing insulin by carbs.
3. **Diabetes rule:** currently withholds nothing. Proposed: keep calories, label the carb target "general estimate — not a carb plan", and add `clinicianEditable: ["carbs"]` (carbs per meal or day from their care team), mirroring the kidney protein pattern. Advisor to confirm.
4. **Connect to glucose:** the new Glucose screen keys off this condition (`tracksGlucose()`). Once the split lands, update `DIABETES` in `apps/mobile/src/domain/glucose.ts`.
5. **PR size:** 25 files and 2,161 lines in one commit is hard to review. Prefer domain + tests, then UI, then rules as separate PRs.

## Food search (Srija): feedback

**Strong:** one `FoodCandidate` shape for both providers. Unknown nutrients stay `null`. Per-100 plausibility caps. Barcode de-duplication across UPC/EAN padding. Recorded fixtures instead of live calls in tests. It's behind the existing access policy.

**Should change:**
1. **Fiber** isn't mapped (USDA 1079, OFF `fiber_100g`). It's needed for D01 and diabetes education.
2. **Configuration:** the USDA API key must be a Functions secret. Confirm App Check and the per-user rate limit before release.
3. **Attribution:** Open Food Facts data is ODbL. Add it to Profile → Open-source credits along with USDA FDC.
4. **Source label in the UI:** show "USDA" vs "Open Food Facts (check the label)" on each result, so patients know which numbers are lab-analysed.
